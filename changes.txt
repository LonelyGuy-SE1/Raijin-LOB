Raijin-LOB — recommended core changes (manual review)

1. add_order partial-apply semantics (src/core/limit_order_book.cpp)
   match_buy/match_sell run before rest_order. If rest fails (pool or level queue full),
   fills are already committed but add_order returns false.
   Test: LimitOrderBookCapacityTest.PartialMatchRestFailsWhenPoolFull
   Options: reserve capacity before match, split API, or document partial-apply contract.

2. execution receipt loss (src/core/limit_order_book.cpp)
   receipt_queue_->push(...) return value is ignored. Full ring drops trades silently.
   Test: LimitOrderBookReceiptTest.FullRingDropsReceiptSilently
   Options: propagate failure, block match on full ring, or expose overflow counter.

3. empty-book sentinel (include/core/limit_order_book.hpp)
   best_bid_tick() / best_ask_tick() return UINT32_MAX when empty. Undocumented in header.
   Tests rely on this. Add documentation or has_best_bid()/has_best_ask() helpers.

4. tombstone cost at touch during match (src/core/limit_order_book.cpp)
   FIXED: clean_front now compacts after 8 consecutive stale pops instead of
   popping one tombstone per loop forever. BM_MatchThroughTombstones should drop
   sharply for high tombstone counts. Single tombstone at front remains O(1) pop.

5. erase_best bitscan on empty side (src/core/limit_order_book.cpp)
   When the last ask level clears, erase_best_ask calls next_ask which scans the
   full price radar (8192 ticks / 128 words). On single-level turnover this adds
   cost every fill. Optional: track side-empty flag or skip scan when word tail is zero.

6. locator cache on monotonic order ids
   Benchmarks must reuse ids for fair comparison. Production sim should pool ids or
   size locators to working set. Monotonic id 1..N touches cold locator[N] each op.

   Optional: fail job if tombstone arg(256) is not slower than arg(0), or if prefill assertions would skip.
